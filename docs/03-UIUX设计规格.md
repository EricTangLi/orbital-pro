# Orbital Pro · UI/UX 设计规格（v1.0）

> 方法：设计原则 → 信息架构 → 设计系统 → 页面规格 → 交互流程 → 无障碍
> 依据：`docs/04` 旧界面设计（9 张官方截图实核）+ `research/00` 论文 + Orbital 旧项目实测教训
> 日期：2026-11-12

## 1 设计原则（先定原则，再画界面）

### 1.1 三条铁律（来自旧项目 docs/04 §1，经用户实测验证）

| # | 铁律 | 为什么 |
|:--:|---|---|
| **1** | **面板是操作台，不是展示板** | TencentDB 原文："Memory Hub Is **Not** a Display Board — It's a Control Panel"。只读列表 + 漂亮图谱 = **数据会烂掉** |
| **2** | **同一状态必须由同一状态机生成** | 旧项目踩过：侧栏角标用体检 warn 数（4），页面显示待办（6）——两个源就有两个数 |
| **3** | **每个数字都要能点进去** | 数字不可点 = 装饰；可点 = 行动入口 |

### 1.2 五条必须避免（旧项目 §5）

| # | 避免 | 旧项目犯了没有 |
|:--:|---|:--:|
| 1 | 拿 README 截图当设计依据 | 没犯 |
| 2 | 把营销叙事当信息架构 | 没犯 |
| 3 | 没有集中设置页 | **犯了**（设置页只有主题） |
| 4 | 状态假绿 | **犯过**（角标与页面不一致） |
| 5 | **只读展示板** | **犯了**（维护页最初只有体检） |

### 1.3 新增（来自本轮论文）

| 原则 | 依据 |
|---|---|
| **渐进披露**（先摘要后详情） | Governed Memory 的渐进式投递，实测省 50% token |
| **每个操作有回滚路径** | 旧项目 docs/04 §9；删除必须软删 + 可恢复 |
| **未测 ≠ 0** | 旧项目 docs/04 §7：没测到显示 `—`，测到 0 显示 `0` |

### 2.1 页面清单（5 个，缺一不可）

| 页面 | 一句话职责 | 核心动作 |
|---|---|---|
| **Agent 详情** | 这个 agent 现在的记忆状态 | 接入 / 断开 / 切换模式 / 验证 / 看统计 |

## 3 设计系统（token 先行，界面后写）

### 3.1 字号（**6 档，不许新增** — v2，ADR-032）

| Token | 值 | 用途 |
|---|---|---|
| `--fs-2xs` | 11px | 时间戳、坐标轴、辅注 |
| `--fs-xs` | 12px | 标签、次要说明 |
| `--fs-sm` / `--fs-md` | 13px | **正文（默认）**；两个名字同值，`--fs-md` 仅为兼容旧类名保留 |
| `--fs-lg` | 15px | 卡片标题 |
| `--fs-xl` | 18px | 页面标题 |
| `--fs-num` | 21px | **指标数字** |
| `--fs-display` | 28px | 唯一的 hero 数字（一屏最多 1 个） |

> ⚠️ v1 的 16/20/26 不在任何设计体系档位上，已按 ADR-032 废弃。**再加档位必须新开 ADR。**

### 3.2 字重（3 档）

| Token | 值 | 用途 |
|---|---|---|
| `--fw-normal` | 400 | 正文 |
| `--fw-medium` | 500 | 标签、次级标题 |
| `--fw-semibold` | 600 | 标题、数字 |

### 3.3 间距（**4px 基数** — v2，ADR-032）

| Token | 值 | 用途 |
|---|---|---|
| `--sp-1` … `--sp-6` | 4 / 8 / 12 / 16 / 24 / 32 | 通用阶梯，不许用中间值 |
| `--sp-page` | 24px | 页面内边距（v1 是 32px，偏松） |
| `--sp-card` | 12px | 卡片内边距（= `--sp-3`；v1 是 20px） |

### 3.4 圆角（2 档 — v2，ADR-032）

| Token | 值 | 用途 |
|---|---|---|
| `--r-control` | **4px** | 按钮、输入框、徽标 |
| `--r-card` | **6px** | 卡片、面板 |

## 4 页面规格

### 4.1 Agent 详情页

```
┌────────────────────────────────────────────────────┐
│ ← DSH                                     [已接入]  │
│                                                    │
│ 模式: Proxy   协议: OpenAI                          │
│ 配置: ~/.dsh/profiles/desktop/cordis.patch.yml     │
│                                                    │
│ ┌──────────┬──────────┬──────────┬──────────┐     │
│ │ 今日注入  │ 今日抽取  │ 平均注入  │ 最近验证  │     │
│ │ 12 次    │ 8 条     │ 3.2 条   │ 2 分钟前  │     │
│ └──────────┴──────────┴──────────┴──────────┘     │
│                                                    │
│ [验证连通性] [切换模式] [断开] [查看日志]            │
└────────────────────────────────────────────────────┘
```

**交互规格**：

| 动作 | 行为 | 失败处理 |
|---|---|---|
| 验证连通性 | 发测试记忆 → 必须返回刚写入的 id | 显示失败原因 + 自动还原 |
| 切换模式 | 弹确认框（写明"会修改 DSH 的配置文件"） | 失败自动回滚 + 显示备份路径 |
| 断开 | 二次确认 + 显示"会删除 orbital 配置段" | 从备份精确还原（sha256 校验） |

#### 4.1.1 回合记忆栏（借 dsh-mnemon 的 turn memory bar，`evidence/05 §6.1①`）

Agent 详情页下方挂**最近运行的记忆回执**，不是一句"已使用记忆"，而是按动作分类计数：

```
DSH · 14:32 那一轮
  召回 4 · 写入 2 · 检索 1 · 检查 12 · 失败 0        [展开]
    ├ 召回 memory_recall("端口配置") → 4 条          [点击跳记忆页]
    ├ 写入 memory_write(scope=shared) → mem_01H...   [点击跳详情]
    └ 失败 EMBEDDING_UNAVAILABLE（已降级 FTS）        [点击看原因]
```

**判据**：每个计数项都能点进它真正操作的那条/那批记忆；点不动就是装饰。

#### 4.1.2 "存入记忆"三步（不是一键静默写入）

1. **候选可编辑**：把要存的内容做成可编辑文本（超长时明确提示"仅载入前 N 字符"）；
2. **选目标**：`本 agent 私有` / `共享` / `某实体` / `由 agent 决定`；
3. **给确定结果**：`已入库` / `已提交，等待提炼` / `内容已存在，没有重复写入` / `超过单条上限 64KB`。

#### 4.1.3 记忆空间/分区卡与**三态空态**（消灭"一片空白不知道坏没坏"）

| 状态 | 文案 | 说明 |
|---|---|---|
| 还没有任何分区 | "还没有记忆分区。接入一个 agent 后会自动创建。" | 首次使用 |
| 有分区但未启用 | "没有启用的分区。打开至少一个读取开关，这里才会聚合。" | 用户关了 |
| 已启用但没内容 | "已启用，但还没有记忆。agent 写入后会显示在这里。" | 空库 |

**禁止**：三种情况都用同一句"暂无数据"。

### 4.2 记忆页（主从双栏）

```
┌──────────────────────────────────────────────────────────────┐
│ [搜索框]        Agent: [全部▾]  类型: [全部▾]  状态: [当前▾]   │
│ ┌──────┬──────┬──────┬──────┐  ← 分层卡可点击过滤            │
│ │L0 1583│L1 166│L2 7 │L3 1 │   ← 分层卡（数字为设计稿示例）
│ │       ⚠ 数据来源见 ADR-031：L0 从 conversations 表 count，
│ │          L1 从 memories count；**不得 GROUP BY layer**（该字段已废弃）                               │
│ └──────┴──────┴──────┴──────┘                               │
├────────────────────────┬─────────────────────────────────────┤
│ 记忆列表                │ 详情                                 │
│ ● 摘要第一行…          │ 内容（可编辑）                        │
│   dsh · 11-12          │ ────────────                        │
│ ● 摘要第二行…          │ 来源: dsh · session-abc             │
│   hermes · 11-11       │ 双时态: 2026-11-01 生效 · 仍有效     │
│                        │ importance 4 · access 12 · pin      │
│                        │ [编辑] [Pin] [删除] [标记失效]       │
└────────────────────────┴─────────────────────────────────────┘
```

**四个操作的交互规格**：

| 操作 | 行为 | 数据影响 |
|---|---|---|
| **编辑** | 行内编辑 → 保存时查重 | 走 guarded 路径（查重 + 双时态） |
| **Pin** | 切换开关 | `pinned = 1`，禁止自动退役 |
| **删除** | 先显示**影响面**："会让 3 个实体、2 条关系失去唯一来源" → 确认 | 软删（可恢复） |
| **标记失效** | 设置 `valid_to = now`，保留历史 | 不再被召回，但可查历史 |

### 4.3 维护页（待办清单，不是体检报告）

```
┌──────────────────────────────────────────────────────┐
│ 待处理 4 项                            [全部处理]     │
├──────────────────────────────────────────────────────┤
│ ⚠ 6 组重复记忆                        [查看并处理 →]  │
│   同一内容存了两条                                     │
│ ⚠ 标签填充率 19%（目标 30%）            [批量补标签]   │
│ ⏱ 8 条记忆没有向量                      [重新计算]    │
│ ○ 27 项体检通过 · 审计链 0 断裂              —        │
└──────────────────────────────────────────────────────┘
```

**点「查看并处理」展开逐组决策**：

```
组 1 / 6
 A │ 内容摘要…              11-11 09:48 · mnemon
 B │ 内容摘要…（相同）       11-11 10:02 · mnemon
   │ [保留A删B] [保留B删A] [合并两者] [都保留]
```

**「合并两者」的关键差异**（旧项目缺）：
- 保留 A 的内容
- **把 B 的标签、实体、关系搬到 A**
- 然后软删 B

### 4.4 设置页（整屏 6 组 + 页内搜索）

```
┌────────────────────────────────────────────────┐
│ 设置                          [🔍 搜索设置项]   │
```

## 5 关键流程（交互设计）

### 5.1 接入新 agent（4 步，每步可回退）

```
① 探测配置 → 显示路径与格式
② 选模式（MCP / Proxy）→ 显示该模式的影响说明
③ 写入前备份 → 原子写入
④ 验证：发测试记忆 → 必须返回刚写入的 id → 成功变绿 / 失败自动还原
```

### 5.2 处理重复（3 种决策，不是 2 种）

```
[保留A删B] [保留B删A] [合并两者]
   ↑           ↑          ↑
  简单        简单      搬标签+关系再删
```

### 5.3 注入统计（从"看不见"到"可判断"）


### 5.4 预算触顶与"空结果"必须可区分（借 dsh-mnemon 的硬失败契约）

| 情况 | 返回 | UI 必须写 |
|---|---|---|
| 检索跑了但没命中 | 空数组 + `scanned=N` | "没有匹配（已检索 N 条）" |
| 检索**没跑**（名额/超时/降级） | `budgetExhausted` / `degraded` + 原因 | "**不是没匹配，是这次没检索**：{原因}" |
| 注入超时被跳过 | `inject_skipped=timeout` | "本轮未注入（超时），对话未受影响" |
| 写入超上限 | `INVALID_ARGUMENT` + 上限值 | "超过单条上限 64KB，请拆分或精简" |

**反例（禁止）**：把"没跑"和"没匹配"都显示成"无结果"——用户会以为记忆丢了。

**关于截断**：预算不足时**在分配阶段裁剪**（各页/各 agent 先分额度），不在拼接阶段悄悄截断；若仍超预算，**直接失败并说明**，而不是输出半截记忆误导模型。
