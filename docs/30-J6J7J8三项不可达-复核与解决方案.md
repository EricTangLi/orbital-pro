## 2 J6 注入统计：真缺开发，方案如下

### 2.1 数据源已经存在（不需要新建表）

`crates/orbital-proxy/src/main.rs:508-538` 的 `record_metric` 每次注入写一行 JSONL：

```
%LOCALAPPDATA%\OrbitalPro\metrics\injection-{YYYY-MM-DD}.jsonl
{ "ts": 1794…, "protocol": "openai", "hits": 3, "tokens": 812,
  "elapsed_ms": 12, "status": "on", "cache": "hit" }
```

| 字段 | 含义 | 可用于 |
|---|---|---|
| `ts` | Unix 秒 | 时间趋势 |
| `protocol` | 协议（openai/…） | 分组 |
| `hits` | 本次注入了几条记忆 | 注入条数 |
| `tokens` | 注入段占多少 token | token 数 |
| `elapsed_ms` | 召回+拼装耗时 | P50/P95 延迟 |
| `status` | `on` / `off` / `timeout` / `skipped` | 注入率、跳过原因 |
| `cache` | `hit` / `miss` | 缓存命中率 |

**约束**：`ADR-008` 规定 proxy 从不写库、只写 JSONL ⇒ 新 IPC 必须**只读文件**，不许写库。

### 2.2 业界同类面板怎么设计（调研结论）

| 来源 | 核心做法 | 对我们的启示 |
|---|---|---|
| [LiteLLM 用量面板](https://docs.litellm.ai/docs/proxy/endpoint_activity.md) | 按 endpoint 统计 token 消耗、成功率，提供 24h/7d/30d 窗口与趋势 | 必须给**时间窗口切换**，不能只有"今日" |
| [LiteLLM Auto-Router 节省面板](https://docs.litellm.ai/blog/auto-router-spend-visibility) | 「Total estimated savings（$ 与 %）」+ **对照基准**（如果每次都用最贵模型会花多少） | 节省率必须有**对照基线**，否则数字没意义 |
| [catop-cachehit](https://github.com/Harzva/catop-cachehit) | cache hit rate / cached tokens / miss tokens / saved USD，按 agent·provider·model 分组 | 命中率与分组是这类面板的标配 |
| [LiteLLM Prometheus 指标族](https://github.com/berriai/litellm/blob/55c9c6af17a9acc4b46e707e8761c4592d0e0954/cookbook/litellm_proxy_server/grafana_dashboard/dashboard_all_metrics/readme.md) | 143 个指标族，含 cache、spend、latency | 不必做 143 个；**指标少而准**更适合桌面应用 |

**共同点**：这类面板都在回答一个问题——**"开这个到底值不值"**，所以核心是 **命中率 + 节省量**，不是"记录了多少次"。

### 2.3 指标设计（分 MVP 与增强）

**MVP（不改进程，只加读取 IPC + 一个卡片）**

| 指标 | 计算 | 为什么要有 |
|---|---|---|
| 今日注入次数 | `status=="on"` 行数 | 判断"有没有真在用" |
| 今日注入条数 | `sum(hits)` | 回答 J6 的"条数" |
| 今日注入 token | `sum(tokens)` | 回答 J6 的"token" |
| 缓存命中率 | `cache=="hit"` / 总行数 | 判断缓存是否值得开 |
| 跳过/超时率 | `status in (off,timeout)` / 总行数 | 发现"注入没生效" |
| 注入延迟 P50/P95 | `elapsed_ms` 分位 | 验证 300ms 超时是否常触发 |
| 近 7 天趋势 | 按日聚合 | 看是否持续在用 |
| 按 agent 分组 | ⚠️ 见下 | 哪个 agent 最受益 |

> ⚠️ **一个当前数据缺项**：JSONL **没有 agent 字段**（proxy 不知道请求来自哪个 agent）。
> 所以"按 agent 分组"**MVP 做不到**。两条路：
> ① 不改数据：只做全局统计（诚实标注"当前不区分 agent"）
> ② 改 proxy：从请求头/URL 推断来源（如 `X-Orbital-Agent`），或按上游 endpoint 分组
> 建议：**MVP 走 ①**，把 ② 作为增强（需 ADR，因为改了 proxy 的观测口径）

**增强（需要小改进程）**

| 指标 | 需要的改动 | 代价 |
|---|---|---|
| **token 节省率**（PRD §7 要求 ≥30%） | proxy 额外记录 `baseline_tokens`（本次请求若**不注入**的估算 token） | 改 `record_metric` + 一次 token 估算（字符数/4 或 tiktoken 轻量版）；**必须写 ADR**，因为这是新的观测口径 |
| 按 agent / 会话分组 | 从 `X-Orbital-Agent` 或会话 id 头取 | 需要 agent 侧配合传头（现有 4 个 agent 要改配置） |
| 导出 CSV | 无（读同一 JSONL） | 低 |

### 2.4 实现方案（MVP）

**后端**（`src-tauri/src/`）

```rust
// 新增 status::injection_stats(days: u32) -> InjectionStats
// 1) 定位目录：LOCALAPPDATA\OrbitalPro\metrics（与 proxy 同源，不硬编码第二份）
// 2) 读取 injection-*.jsonl（只读最近 N 天，逐行 serde_json 解析，坏行跳过并计数）
// 3) 聚合：counts / sum(hits) / sum(tokens) / p50 / p95 / cache_hit_rate / status 分布 / 按日序列
// 4) 目录或文件不存在 → 返回 empty=true（前端显示"还没开启注入"，不报错）
```

**前端**（`src/App.tsx` 状态页，放在「一键体检」之上）

```
┌ 注入统计 ────────────────── 最近 [今日|7天|30天] ┐
│ 注入 128 次 · 486 条 · 21,304 token              │
│ 缓存命中 82%    跳过/超时 3 次     P95 14ms      │
│ ▁▃▅▂▇▆▄  近 7 天趋势                             │
│ 提示：注入默认关闭，需在 agent 侧设 ORBITAL_INJECT=1 │
└──────────────────────────────────────────────────┘
```

**关键取舍**

- **只读 JSONL，不写库**（ADR-008 红线），也不新增 SQLite 表
- **不轮询太频**：状态页现有 3 秒轮询是给进程状态的；统计改为「切窗口/点刷新时读」，避免每 3 秒扫文件
- **空态不假绿**：文件不存在、有文件但 0 行、注入了但 `status` 全是 `off`——三种空态要分别说明（对齐 M9-01 的 waived 口径）
- **不引入图表库**：`docs/10` 只特批 recharts + Cytoscape；趋势用现有 `trend-col` 样式（总览页已有同类柱状）

### 2.5 验收（可执行）

| # | 验收 | 怎么验 |
|:--:|---|---|
| 1 | 空态 | 删/改 metrics 目录 → 卡片显示"还没开启注入"，不报错、不显 0% 假绿 |
| 2 | 有数据 | 造 3 天 fixture JSONL（含 on/off/timeout、hit/miss）→ 指标与手算一致 |
| 3 | 分位 | fixture 含已知 elapsed 分布 → P95 与手算一致 |
| 4 | 坏行 | fixture 塞一行非法 JSON → 跳过并显示"跳过 N 行" |
| 5 | 窗口切换 | 今日/7 天/30 天切换，数字随窗口变化 |
| 6 | 不写库 | 对比前后 SQLite 文件 hash 不变 |

## 3 J7 / J8：重新打包 + 真机验证（不写代码）

### 3.1 打包前必须先做（否则会再犯同一个错）

1. **版本号统一**：`package.json` `0.1.0` / `tauri.conf.json` `0.72.0` / `Cargo.toml` `0.1.0` / `CHANGELOG` `0.83.0` —— 四处不一致
2. **确认 `beforeBuildCommand` 生效**：`tauri.conf.json` 已配 `npm run build`（历史坑：缺了它会静默用旧 dist）
3. **构建顺序**：`npm run build` → `cargo tauri build`（`src-tauri` 是独立 workspace）→ 产出 `bundle/nsis/*.exe`

### 3.2 打包后真机验收

| 项 | 验法 | 证据 |
|:--:|---|---|
| J8 一键体检 | 状态页应出现「一键体检 / 共 11 项」卡片；点一项展开判据 | 截图 + 11 项计数 |
| J7 一键接入 | 需先制造"未接入"状态：`orbital-mcp --detach <agent>`（ADR-029：只删 orbital 条目，有 `.bak.orbital` 兜底）→ 连接页应出现「一键接入」→ 点它 → 再 `--attach` 回来 | 截图（按钮出现 → 点击 → 已接入） |
| 回归 | `cargo test` 全绿 + MCP 冒烟 + 注入冒烟 11/11 | 命令输出 |

> J7 验证的风险控制：选 **pi**（配置最简单、`.pi/agent/mcp.json` 有 `.bak.orbital`）；流程 detach → 截图 → attach → 再截图确认恢复。**不碰 hermes / dsh 的配置**。

### 3.3 为什么这一步必须先做

现在让内测用户装，装到的是 `20:15` 的旧版：没体检、没一键接入、没有 21:25 之后任何界面改动。
**内测反馈会有一半是"版本旧"造成的假问题**，浪费用户耐心，也污染证据。

## 7 不要做的事

- **不要**为 J6 新建 SQLite 表存统计（ADR-008：proxy 从不写库；JSONL 就是数据源）
- **不要**让状态页每 3 秒扫 JSONL（进程状态轮询与文件统计是两种节奏）
- **不要**在没有 baseline 的情况下宣称"节省了 X%"（LiteLLM 的节省面板都要写清对照基准）
- **不要**为了验证 J7 去改 hermes/dsh 的配置（只动 pi，且有 `.bak.orbital`）
- **不要**只重新打包不验 J7/J8（`dist` 比 `exe` 新这件事本身说明"构建过了就以为装了"）
