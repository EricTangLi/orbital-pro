# 踩坑与反模式（v1.0）

> 每条四段式：**症状 / 根因 / 判据 / 规避**。
> 来源分两类：`旧项目`（`agent-memory-hub` 16 小时实证）、`外部`（开源项目真实 issue/论文）。
> 规则：只在有真实拦截案例时才写进来；没有案例的"感悟"不进本文。

## A. 记忆系统特有的反模式（外部实证）

### A1 静默丢失：返回成功，但什么都没落库

- **症状**：调用方拿到 memory id，事后查不到；日志无异常。
- **真实案例**：
  - mem0 #4985：切换 embedding provider 后 pgvector 集合仍是旧维度，写入"成功返回 id"但未落库。
  - mem0 #5245：批量 embedding 部分失败时只在 WARNING 记录，不向调用方抛异常。
  - TencentDB #1432：`/health` 报 `status=ok`，而 store 已 degraded，捕获/L1 写入/搜索全部静默 no-op。
  - TencentDB #1523：瞬时 LLM 失败永久推进游标，失败会话内容静默丢失且永不重试。
- **根因**：失败发生在**写入期**，而监控都盯着**检索期**；异常被 catch 后只记日志。
- **判据**：写入返回 id 之后，必须能用该 id 查回同一条内容；查不回就是 bug。
- **规避**：写入返回 `accepted_id` + `GET /memory/:id` 回查 + GUI 明确区分"已接受 ≠ 已入库"；30 天回查抽检。

### A2 错误退役：把仍然为真的事实静默删掉

- **症状**：新事实写入后，一条更宽的旧事实被标失效；用户问"现在用什么"答错。
- **真实案例**：Graphiti 的边失效（invalidation）在整张图里找矛盾候选（过滤器为空），一次 LLM 返回裸索引列表就永久置 `invalid_at`。
  - 规模：4,651 条边 / 526 条被退役；可归因的 479 条里 **75.6%** 找不到任何合理替代（Wilson 95% CI [71.5%, 79.2%]）；人工盲标 40 条分层样本 **28/40 = 70%** 是错误退役（CI [54.6%, 81.9%]）。
  - 典型误判："A 服务用 PostgreSQL"这种更窄的新事实，会退役"平台用 Neo4j"这种更宽的真事实。
- **根因**：把"共享词汇"当"矛盾"；把不可逆操作交给 LLM 自动决定。
- **判据**：退役操作必须能回答"替代它的是什么"；答不出来就不许退役。
- **规避**：见 `docs/07` ADR-009——衰减只影响排序、退役进候选列表、人确认、软删可恢复。

### A3 共享句柄被上一次写入改写，读到别人的数据

- **症状**：多租户/多 group 场景下，读请求静默返回空，或读到上一个 group 的数据。
- **真实案例**：Graphiti #1795：`add_episode` 里 `self.driver = self.driver.clone(database=group_id)` 永久改写共享 driver；长生命周期客户端写完之后，读请求会去最后写入的那个 group 的图。
- **根因**：连接/句柄是共享可变状态，隔离靠"临时改一下"。
- **判据**：隔离必须在**查询条件里**（`WHERE agent=?`），不能靠"切换连接之后的行为"。
- **规避**：SQL 层硬门控 + 每请求显式传作用域 + 对抗查询测试（160 次）。

### A4 记忆污染直接改变 agent 行为

- **症状**：agent 表现得过度迎合、反复被同一批旧记忆带偏。
- **真实案例**：
  - 78 任务子集上，**持续暴露冲突记忆**是唯一让所有模型都掉点的条件，伤害随重复暴露累积（arXiv 2607.10608）。
  - 部署 5 天 9,284 条记忆抽 200 条：**66% 是 SSH 调试步骤垃圾**，真正有长期价值的约 3%（Hindsight 自述）。
- **根因**：没有"什么值得记"的准入；冲突条目照样被注入。
- **判据**：冲突条目必须 100% 不进注入；每类记忆要有准入规则。
- **规避**：冲突收件箱隔离 + `origin`/`confidence` + 分层准入（`docs/04`）。

### A5 "纠错没有自动挡"

- **症状**：新事实写进图谱了，但问"现在用什么"仍答旧的。
- **真实案例**：Cognee 1.6.0 本地实测（作者结论：当"可显式增删的本地库"用才对得上，当"会自己更新"的记忆用会落空）。
- **根因**：写入与检索之间缺少"以新替旧"的裁决。
- **判据**：同一实体同一属性写入新值后，检索必须以新值为准且能给出旧值历史。
- **规避**：`superseded_by` 链 + 双时态 + 冲突检测（`docs/04`）。

### A6 单项目数字被当成赛道结论

- **症状**：报告写"静默失败占 13.8%，最高频"。
- **根因**：13.8% 是 **TencentDB 一家** 42/305 条 open issue 标题占比；不同项目口径不可直接比。
- **判据**：引用比例必须写清"分子/分母/对象/日期"。
- **规避**：所有数字带口径；跨项目比较只比"量级/有无"，不比精确百分比（本机教训，见 `AGENTS.md §3.2`）。

### A7 拿合成探针数据当真实负载

- **症状**：报告写"mnemon 有 77,490 条边 / 2,920 条记忆，比值 26:1，说明它是知识图谱"。
- **事实**（本机实测）：77,490 条边在 `verifyprobe` 探针库（66MB），那 2,920 条是 17~48 字的**同模板文本**，去重后 2,913，语义余弦 **p50=0.9965** ⇒ 自动边吃满每节点上限；`causal` 一条都没有。**真实库 `shared` 只有 2,708 条边 / 139 条活跃记忆**，构成是 entity 54.65% + temporal 42.98% + semantic 2.14%。
- **根因**：探针库与真实库在同一个 `~/.mnemon/data/` 下，且插件的 6 个 space **全部 `active:true`**，读作用域不分。
- **判据**：引用任何"库规模/比例"前，先确认它来自**生产库**还是**合成/评测库**；用 `sqlite` 直查而不是看文档。
- **规避**：本文与 `docs/04` 所有规模数字必须标库名；涉及阈值的结论必须在真实库上复测（实测：cosine 0.99 时把阈值从 0.80 提到 0.85 **一条边都不会少**，阈值不是控边杠杆，配额+margin 才是）。

### A8 "字段存在"不等于"值是最新的"

- **症状**：看到 `effective_importance` 列有值，就认为衰减机制在正常工作。
- **事实**：mnemon 的 EI 是写入时快照，读路径从不刷新；实测 36 行 EI 全等 0.75，实际按公式应 ≈4.18。
- **判据**：列有值 ⇒ 查"谁在什么时候算的"；没有"计算时间戳"的派生值一律不可信。
- **规避**：见 `docs/07` ADR-013（读时计算 + `ei_computed_at` 校验）。

## B. 工程与流程反模式（旧项目实证）

### B1 读了任务分解就开工

- **症状**：11 个阶段做完，才发现从未读过界面设计文档。
- **根因**：`docs/17-任务分解` 只写"W3 渲染四个页面"，没写"十交互/五避免/三铁律"；AI 把"渲染出页面"当成"实现设计"。
- **判据**：开工前能逐条复述设计文档的验收条目。
- **规避**：`AGENTS.md §0` 强制读对应设计文档；`docs/06 §7` 文档对照表。

### B2 按周打勾，不按验收

- **症状**：W3 打完勾后再没回看设计。
- **根因**：进度指标是"任务完成数"，不是"验收条目通过数"。
- **规避**：`docs/05` 每个里程碑用可勾选验收；`remaining` 必须写。

### B3 做成看板而不是操作台

- **症状**：维护页只有体检列表，显示"6 组重复"但没有任何修复入口。
- **根因**：把"展示状态"当成"提供操作"。
- **判据**：每个数字都能点进对应列表；每个问题都有"现在该做什么"。
- **规避**：`AGENTS.md` 红线 3。

### B4 自己改架构并写 ADR 说服自己

- **症状**：为"不要点 4 个 exe"把三进程改成单进程多模式，用实测数据论证。
- **根因**：把"用户体验"与"架构约束"对立起来，且没问用户。
- **规避**：`AGENTS.md` 红线 10；ADR 必须写"被否方案"。

### B5 闸门 `exit 0` 吞掉所有 FAIL

- **症状**：任何失败都输出 `EXITCODE=0`。
- **根因**：`exit 0` 写在 `Step` 的 scriptblock 里，直接退出整个脚本，汇总行永远不打印。
- **判据**：闸门必须能做红绿对照——故意制造一个 FAIL，退出码必须非 0。
- **规避**：每个校验脚本上线前跑一次"已知为假"的对照。

### B6 状态数不一致（角标 4 vs 待办 6）

- **症状**：侧栏角标显示 4，页面显示 6 组重复。
- **根因**：两个不同的数据源（体检 warn 数 vs 待办数）。
- **规避**：同一状态必须由同一状态机生成；`docs/03` 铁律 2。

### B7 `cargo check` 过就以为能跑

- **症状**：截图全来自 `vite preview`，桌面形态从未真正运行。
- **判据**：出 exe + 对真窗口截图，且副标题是"实时数据"。
- **规避**：`AGENTS.md` DoD。

### B8 把密钥打印进会话

- **症状**：探测配置时把 `apiKey` 打进会话存档，无法回收。
- **规避**：打印前脱敏；探测脚本默认掩码。

### B9 孤儿进程杀掉后不等端口释放就重启 → `BIND_FAIL (os error 10048)`

- **症状**：T-M1-00 Spike 实测：检测到孤儿 → `taskkill` → 立即 `spawn` → 子进程报 `BIND_FAIL 10048（通常每个套接字地址只允许使用一次）` 并以 exit 2 退出，启动器再重启一次才成功。
- **根因**：`taskkill /F` 返回时进程虽已终止，但**监听套接字尚未由 OS 回收**；立即 bind 必然失败。
- **判据**：kill 后必须轮询 `connect` 直到端口不可连（或超时）再 spawn。
- **规避**：实现 `wait_port_free(port, 3000)`（100ms 轮询），超时未释放则记 `PORT_STILL_BUSY` 并顺延端口（禁止静默换端口）。

### B10 重启后不刷新运行态文件 → 退出清理杀错 pid，留孤儿

- **症状**：Spike 实测：子进程崩溃重启后，`launcher.ndjson` 里仍是旧 pid；退出时按文件清理，杀的是已死的旧进程，**新进程变成孤儿**（`final_count=1`）。
- **根因**：运行态只在启动时写一次。
- **判据**：任何会改变进程 pid 的动作（spawn / restart）之后，都必须**立刻重写**运行态。
- **规避**：`update_state(gui_pid, &procs)` 在每次 spawn 与 restart 后调用；退出时"按 child kill + 按运行态兜底清理"双保险。

### B11 判据用 pid 变化判断"重启成功"不可靠

- **症状**：Spike 第一次跑 T4 判 FAIL——杀了 core、重启成功，但 Windows **复用了同一个 pid**，判据（pid 必须变）给出假阴性。
- **根因**：pid 不是唯一身份（会被复用）。
- **规避**：用**行为证据**判断：重启后 `connect` 端口并读取服务返回的角色（`"core"`），或看启动器日志的 `CHILD_EXIT`+`RESTART`；pid 只作辅助信息。

### B12 编译报"拒绝访问 os error 5"不是代码错，是旧进程占着 exe

- **症状**：`cargo build --release` 报 `failed to remove file ...orbital-spike.exe: 拒绝访问 (os error 5)`。
- **根因**：上一轮测试留下的进程还在跑，Windows 锁住 exe 文件。
- **规避**：先 `Get-Process <name> | Stop-Process -Force` 再编译；测试脚本收尾必须清理进程。

### B13 PowerShell 函数返回单元素被展开 → `.Count` 为空，判据假阴性

- **症状**：Spike 的 A1 判 FAIL，但日志里明明有 `msedgewebview2.exe` 子进程。
- **根因**：`function WebviewKids { @(Kids $x | Where-Object {...}) }` 这类函数返回**单个对象**时被 PowerShell 展开为标量，再经函数边界后 `.Count` 取到 `$null`，字符串拼接变成空 ⇒ 判据 `($wv.Count -gt 0)` 为假。
- **判据**：先看"被测对象真的坏了吗"——日志与判据矛盾时，先怀疑判据。
- **规避**：**不要用返回数组的函数做 Count 判据**；在调用点直接内联 `@(...)` 强制数组：
  ```powershell
  $kids = @(Get-CimInstance Win32_Process -Filter "ParentProcessId=$procId")
  $wv   = @($kids | Where-Object { $_.Name -like 'msedgewebview2*' })
  ```
  另：`$pid` 是 PowerShell 只读内置变量，**不能当函数参数名**（会报 `VariableNotWritable`）。

### B14 tauri-build 的两个硬要求（Spike 实测）

- **症状 1**：`error: icons/icon.ico not found; required for generating a Windows Resource file`。
  → **规避**：任何 Tauri 工程都必须有 `icons/icon.ico`（哪怕 32×32 的纯色图）。
- **症状 2**：`The frontendDist configuration is set to "../dist" but this path doesn't exist`。
  → **根因**：`frontendDist` 是**相对 `tauri.conf.json` 所在目录**解析的，不是相对项目根。
  → **规避**：把前端产物放在 `src-tauri/dist` 并写 `"./dist"`，或写正确的相对层级。
- **附加**：没有窗口时 Tauri **不会**创建 WebView2 进程；要验证"GUI 有 WebView2"的对照实验，必须给 GUI 至少一个窗口（可用 `"visible": false`）。

## C. 本机环境坑（Windows / PowerShell / Python）

| # | 症状 | 根因 | 规避 |
|:--:|---|---|---|
| C1 | `Get-Content` 读单行文件返回 String，`[0]` 取到首字符 | PowerShell 语义 | 用 `@(...)` 强转数组或用 `-Raw` |
| C2 | `-replace` 多行写字面 `` `n `` | PowerShell 转义 | 用 `edit` 工具做精确替换 |
| C3 | Python httpx 报 `InvalidURL: Invalid port: ':1]'` 且无结果 | `NO_PROXY` 含 `[::1]` | 子进程显式 `NO_PROXY=localhost,127.0.0.1,::1` |
| C4 | 下载静默停滞 | `HTTP_PROXY` 指向 SOCKS5 端口 | 清空代理变量再试 |
| C5 | D 盘写文件报 EISDIR | exFAT 不支持硬链接，工具用硬链接做原子写 | 先写 C 盘再复制 |
| C6 | `subprocess` 调 `.cmd` 失败 | Windows 后缀解析 | `cmd /c "..."` |
| C7 | pnpm 对两个 registry 都 `UND_ERR_DESTROYED` | 本机网络/registry | 改用 npm |
| C8 | 同一脚本 `pwsh` 跑 PASS、被 AWO-Task 跑却 FAIL（报 `Missing '=' operator after key in hash literal`） | **脚本是 UTF-8 无 BOM**，PowerShell 5.1 按 GBK 读中文 → 乱码 → 哈希字面量语法错 | 含中文的 `.ps1` 一律存 **UTF-8 with BOM**（`[System.IO.File]::WriteAllText($p,$c,(New-Object System.Text.UTF8Encoding($true)))`）；并**在 5.1 与 7 两个壳里各跑一次**验证 |
| C9 | 修好 C8 后，用 `edit` 工具改同一脚本 → **BOM 又被丢掉**，问题复发 | `edit`/`write` 以 UTF-8 无 BOM 重写文件 | **每次用 `edit` 改过 `.ps1` 之后，必须重新加 BOM 并双壳复跑**；或改完后立刻跑一次闸门自检 |
