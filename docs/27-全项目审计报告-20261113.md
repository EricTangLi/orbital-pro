## 1 已核实的"没问题"（附证据）

### 1.1 测试：69 全绿，连跑 3 次无 flaky

```
第 1 次: 65 passed (12.14s) + 1 + 3
第 2 次: 65 passed (15.72s) + 1 + 3
第 3 次: 65 passed (12.13s) + 1 + 3
```

**昨天修的 flaky 是真修好了**：原 `rate_limit` 测试把全局 `ORBITAL_RATE_LIMIT_PER_MIN=2`，
并发跑时影响其他 18 处 `env()`；改成模块级 `TEST_LOCK` 由 `env()` 持有整条测试的 guard。
代价是测试从 ~3s 变 ~12s，**这个代价是值得的**（假绿比慢更危险）。

### 1.2 SQL 拼接安全

`src-tauri/src/data.rs` 的 `list_memories` 用 `format!` 拼 `where_sql`，但：
- `where_parts` 里**全是硬编码常量**（`"agent_id = ?"`、`"content LIKE ?"`）
- 用户输入全走 `?` 参数化（`args.push(...)` + `params_from_iter`）
- `todo` 筛选的 4 个分支也是硬编码 SQL 片段

⇒ **无注入风险**（这是"看起来危险实则安全"，避免误报）。

### 1.3 GUI 特权删除的设计是严谨的

`forget_local_owner`（ADR-034）：
```rust
let owner = self.owner_of(id)?;              // 从库查真实 owner
self.forget(&VerifiedAgent::for_local_owner(owner), id, mode)  // 走正常校验
```

**为什么不破坏 ADR-005**：它**不接受请求参数当身份**（注释明确写"只从库里查"），
而是查真实的 `agent_id` 再构造身份，仍走 `forget` 的完整校验。
⇒ 无 token 的 GUI 能操作，但**不能伪造身份**。

### 1.4 `soft_delete_then_restore_is_byte_identical` 已存在

`service.rs:1835`，测试通过。**我一开始误判为"缺失"**，原因是我 grep 时
`Select-Object -First 10` 把结果截断了（`content` 关键词命中太多行）。
⇒ 又一次印证本机铁律：**报异常前先确认不是自己的判据写错**。
