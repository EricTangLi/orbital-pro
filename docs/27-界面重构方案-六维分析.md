# 界面重构方案 · 六维分析（2026-11-13）

> 性质：**只分析、提方案，不修改代码**（用户明确要求）。
> 方法：先调研一手设计规范，再拿四条标杆的**实测参数**对照我们界面的**实际值**，最后给可执行建议。
> 无法从资料或代码中准确得到的数值，都标了「估计值」。

---

## 0 结论摘要（先给判断）

我们界面的**底子是对的**：Radix 十二步色阶、4px 间距基数、低圆角、无渐变/无纹理/无毛玻璃。
问题不在"审美跑偏"，而在**四个"缺"**：

| 缺什么 | 具体表现 | 影响 |
|---|---|---|
| **缺层级压缩** | 页面 `#fcfcfd` → 卡片 `#ffffff`，但卡片边框 `#d9d9e0` 太抢眼 | 读起来是"一格一格的表格"，不是"一块块浮起的板" |
| **缺 elevation 语义** | 全站只有 2 档阴影（卡片/弹窗） | 下拉、提示、工具条没有"高度"，层次全靠边框撑 |
| **缺字重中间档** | 只有 400/500/600 | 强调只能用 600 砸，做不到"克制但有层级" |
| **缺动效** | 全站 4 处 `transition`，其中 2 处是 `none` | 交互是"瞬移"的，按钮 hover、弹窗出现、页面切换都没过渡 |

**我的总体建议：不推翻重做，做一次"收敛 + 补语义"的重构。** 底层的 Radix + 4px 网格已经是主流做法，换掉只会带来新风险。

| **Linear 设计参数**（第三方整理的 DESIGN.md，含实测值） | 全套：surface 层级、510/590 字重、负字距、radius 2–8、ring shadow、ghost 按钮 | Linear 是我们用户明示偏好的风格，且它是"数据密集 + 精致"的标杆 |

> Geist 两条最值得抄的纪律（原文）：
> - **"Draw each border once"**（每条边框只画一次——别用 border + shadow 叠出双线）

## 2 六个维度逐项分析

### 2.1 配色：背景、文字、强调色怎么用，各占多少

**我们现在的实际值**（读自 `src/styles.css`）：

| 角色 | 值 | 说明 |
|---|---|---|
| 页面底 `--bg-canvas` | `#fcfcfd`（Radix gray-1） | 几乎白 |
| 卡片底 `--bg-surface` | `#ffffff` | **纯白** |
| 内嵌区 `--bg-sunken` | `#f0f0f3`（gray-3） | |
| 边框 `--border-subtle` | `#d9d9e0`（gray-6） | |
| 主文字 `--text-primary` | `#1c2024`（gray-12） | |
| 次级文字 | `#60646c`（gray-11） | |
| 三级文字 | `#8b8d98`（gray-9） | |
| 强调 `--accent` | `#5b5bd6`（indigo-9） | |
| 语义 | ok `#218358` / warn `#4f3422` / danger `#ce2c31` | |

**标杆怎么做的**

- **Linear 的核心手法**：整个界面只用**极窄的亮度范围**（luminance 0 → 0.089），相邻层只差 **1–7 个 RGB 值**：
  `8,9,10` → `9,10,11` → `15,16,17` → `18,19,20` → `22,23,24`。
  它的分组逻辑不是靠留白，而是**"靠面色相近来归组"**（原文：visual proximity through surface color rather than whitespace）。
- **Linear 的强调色**：`#5E6AD2` —— 一个**压低饱和度**的靛蓝。它明确写了 **"Don't use saturated accent colors"**（别用高饱和强调色）。
- **Geist 的色阶分工**：Color 1–3 = 组件背景（默认/hover/active）；Color 4–6 = 边框（默认/hover/active）；Color 9–10 = 文字（次级/主）。**边框和背景是两套独立阶梯**，不是同一个色反复调透明度。

**通俗解释**：
> 现在我们的"标题栏—卡片—页面底"三层，是靠**边框线**分开的，所以看起来像 Excel 表格。
> Linear 的做法是**不画那么多线，改用"颜色深浅差一点点"来分层**——深色主题上就是"几乎看不见的灰阶变化"，浅色主题同理。

**给我们的建议**

| 项 | 现在 | 建议 | 依据 |
|---|---|---|---|
| 卡片底 | 纯白 `#ffffff` | 改 **gray-1** `#fcfcfd`，页面底改 **gray-2** `#f9f9fb` | 让"卡片比页面亮一点"，形成浮起感（Linear 同思路，浅色需反向） |
| 卡片边框 | `gray-6` `#d9d9e0` | 降到 **gray-4** `#e8e8ec`，或改用 ring shadow `0 0 0 1px rgba(0,0,0,.06)` | Geist "draw each border once" + Linear ring shadow |
| 语义色用法 | 指标卡**整块背景**染色（黄/绿/紫） | 只染**数字与图标**，背景保持中性 | 语义色面积现在偏大，整块黄会压过内容 |
| 配色占比（**估计值**） | 中性 80% / 彩色 20% | **中性 88% / 强调 7% / 语义 5%** | 按 Linear 的克制程度估；数据密集页彩色面积越小越高级 |

> ⚠️ **别做的事**：不要把强调色提亮（`#5b5bd6` 已经很接近 Linear 的 `#5E6AD2`）。提亮会让它从"平静的权威"变成"廉价的按钮蓝"。

### 2.2 布局与留白：区域划分、疏密、对齐、间距

**我们现在的实际值**：

| 项 | 值 |
|---|---|
| 侧栏 | **固定 220px**，无收起 |
| 内容区 | `max-width: 1160px`（另有 1320px 的旧定义被覆盖） |
| 页面内边距 | 上 24 / 左右 16 / 下 32（`--sp-5 / --sp-4 / --sp-6`） |
| 卡片内边距 | 12px（`--sp-3`） |
| 网格间距 | 指标卡 8px / 两栏 12px / 内容块 16px |
| 正文行高 | 1.55 |

**标杆怎么做的**

- **Linear**：正文 **16px / 行高 24px（1.5）**，段落 15px / 1.6。结构元素（body/section/header/footer）**全部 0 padding**，间距由组件自己管——这是"组件级间距"而不是"全局间距"。
- **Linear 的宽度策略**：不做固定 max-width 居中，而是**内容填满 + 局部最大宽**，因为在 2K 屏上固定 1160 会留下大片死白。
- **Geist**：明确建议"三段断点都设值，让布局在手机/平板/桌面之间可预测地流动"。

**通俗解释**：
> 你现在窗口宽 2089px，内容最大 1160px —— 左右各浪费约 **460px**（估计值）。
> 换算成观感，就是"中间一小条内容浮在大白板上"。
> Linear 的做法是让内容**随窗口变宽而变宽**，只在极宽屏才锁上限。

**给我们的建议**

| 项 | 现在 | 建议 | 备注 |
|---|---|---|---|
| 内容最大宽 | 1160px | **1320–1440px**（估计值） | 2K 屏能少浪费约 200px；或改成"跟随窗口，超过 1600 才锁" |
| 页面内边距 | 16 左右 | **20–24**（估计值） | 视上一条一起调，别两个都放大 |
| 侧栏 | 220 固定 | 加**收起态 56px**（icon-only） | 数据密集页能多出 164px |
| 行高 | 1.55 | 正文 **1.45–1.5**（估计值） | 13px 正文配 1.55 偏松，读起来散 |
| 对齐 | 卡片内 12px | 建议做**一条 4px 基线**贯穿全站（标题、文字、图标都落在 4 的倍数上） | 现在 10px/14px 的按钮 padding 不在 4 网格上 |

### 2.3 字体与层级：标题、正文、辅助信息怎么区分

**我们现在的实际值**：

| token | 值 | 用途 |
|---|---|---|
| `--fs-2xs` | 11px | 辅注、徽章 |
| `--fs-xs` | 12px | 标签 |
| `--fs-sm` / `--fs-md` | **13px / 13px** | 正文（**两个名字同值**） |
| `--fs-lg` | 15px | 卡片标题 |
| `--fs-xl` | 18px | 页面标题 |
| `--fs-num` | 21px | 指标数字 |
| `--fs-display` | 28px | hero 数字 |
| 字重 | 400 / 500 / 600 | |
| 行高 | 1.55 正文 / 1.35 紧凑 | |

**标杆怎么做的**

- **Linear 的字重是 510 / 590**（不是 500 / 600）。这是变量字体才有的中间值，原文称它是"signature choice"：
  > 510 让强调"被感知而不被叫喊"，590 让层级"是校准出来的而不是跳档的"。
  并且它明确写了 **"Don't use weight 600 or 700"**。
- **Linear 的负字距随字号递增**：16px 正常 → 40px `-0.88px` → 64px `-1.408px`。大字号必须"收紧"才不散。
- **Geist 把文字分成 4 类**，关键区别是：
  - **Label**＝单行（行高充裕，用来配图标）
  - **Copy**＝多行（行高更高）
  - 同一个 14px，在 Label 和 Copy 里的行高不同。
- **Linear 的 15/16 分工**：结构 UI 用 16px，流动内容用 15px。

**通俗解释**：
> "标题/正文/辅助"这种三分法不够用。真正要分的是**"单行的标签"**和**"多行的文字"**——它们虽然可能同字号，但**行高应该不一样**（标签行高紧，正文行高松）。
> 另外我们现在的"强调"只有 600 一档，砸下去太重；用 510/590 可以做到"有层级但不吵"。

**给我们的建议**

| 项 | 现在 | 建议 |
|---|---|---|
| 字号档位 | 7 档（含 2 档同值） | **收敛到 6 档**：11 / 12 / 13 / 15 / 18 / 21（28 只给 hero，可保留） |
| 重复 token | `--fs-sm` 与 `--fs-md` 都是 13 | 保留一个，另一个标记 deprecated（现在两个名字会让人写错） |
| 字重 | 400/500/600 | **改为 400 / 510 / 590**（Inter Variable 原生支持）；600 只在极少数地方保留 |
| 标题负字距 | 只有 `h1 -0.025em` | 18px `-0.24px`、21px `-0.3px`、28px `-0.4px`（**估计值**，按 Linear 的比例推） |
| 行高 | 1.55 通用 | **拆两种**：Label 类 1.4 / Copy 类 1.55；表格与列表用 1.4 |
| 数字 | 已用 `tabular-nums` ✅ | 保持，并给指标数字加 `-0.02em` |

### 2.4 形状与比例：卡片、按钮、图标的大小、圆角、边框

**我们现在的实际值**：

| 项 | 值 |
|---|---|
| 圆角 | 控件 **4px** / 卡片 **6px** / 全圆 9999（有 token 但基本没用） |
| 卡片内边距 | 12px |
| 按钮 | `padding: 10px 14px` + 13px 字 → 高约 **33px**（估计值） |
| 图标 | Lucide，尺寸未统一（16/18/20 混用） |
| 边框 | 1px 实线 `gray-6` |
| 徽章 | 4px 圆角小方块 |

**标杆怎么做的**

- **Linear 的圆角上限是 8px，且明确写"不要超过 8"**：
  `2 / 4 / 5 / 6 / 8 / 50% / 9999`。原文：**"Don't add border-radius above 8px for rectangular elements"**（不要给矩形元素加 12、16 这类"友善的"圆角）。
- **Linear 的按钮默认是 ghost**（透明背景 + `#8A8F98` 灰字），只有主 CTA 才有底色。它靠"上下文"而不是"字重/底色"来表达可点。
- **Geist Materials 把圆角和 elevation 绑在一起**：base 6px、medium 12px、fullscreen 16px——**同一档高度就对应一个圆角**。

**通俗解释**：
> 圆角不是"越大越友善"。Linear 的圆角最大 8px，卡片就是 8，按钮 6——**刻意的不圆**，因为要"工程感"不是"玩具感"。
> 我们现在的 4/6 是合适的，**不需要往 12 走**。真正缺的是**"胶囊"**（tag/badge 用 9999）和**图标尺寸统一**。

**给我们的建议**

| 项 | 现在 | 建议 |
|---|---|---|
| 圆角 | 4 / 6 | **保持**，补一档 **pill 9999** 给徽章/标签 |
| 卡片圆角 | 6 | 可考虑 **8**（对齐 Linear 的卡片值），但需与 elevation 一起定 |
| 按钮高度 | 33px（估计） | 提到 **34–36px**（估计值），并保证 `padding` 落在 4 的倍数上（现在 10/14 不在网格上） |
| 图标 | 混用 16/18/20 | 统一 **16（行内）/ 20（按钮内）** 两档 |
| 徽章 | 4px 方块 | 改 **pill**，`padding: 2px 8px` |
| 边框 | 1px `gray-6` | 见 2.1：降一档或改 ring shadow |

### 2.5 材质与光影：表面质感、阴影方向、明暗关系

**我们现在的实际值**：

| 项 | 值 |
|---|---|
| 卡片阴影 | `0 1px 2px rgba(28,32,36,.04)` —— 只有这一档 |
| 弹层阴影 | `0 8px 24px rgba(28,32,36,.12)` |
| 边框 | `1px solid gray-6` |
| 毛玻璃 | **已全部移除**（昨天 ADR-033 做的）✅ |

**标杆怎么做的**

- **Linear 只有 4 档纵深**，且全部是**纯黑透明**，没有彩色阴影：
  - Hairline：`0px 1.2px 0px rgba(0,0,0,.03)`（一条"铅笔线"）
  - **Ring**：`0 0 0 1px rgba(0,0,0,.33)`（用"只有扩散、没有模糊"的阴影当边框）
  - Elevated：**五层叠加**，从 0% 到 8% 逐层加深（"阴影工程，不是阴影装饰"）
  - Press：`0px 1px 0px rgba(0,0,0,.4)`（按下时唯一的重阴影）
- **Linear 明确：不要彩色阴影**（"Don't apply shadows with colored tints"）。
- **Geist Materials：7 档 semantic elevation**，且"**不要在同一个元素上叠两个材质**"、"**选能读作抬升的最低档**"。

**通俗解释**：
> 现在我们有"卡片"和"弹窗"两档阴影，但**下拉菜单、提示条、悬浮工具条**都用卡片那档——它们本该"更高"。
> 另外 Linear 的"ring shadow"很值得抄：它用**1px 扩散阴影**代替边框，好处是**边框不会和阴影打架**（我们现在是 border + shadow 两层，正是 Geist 说的"画两次边框"）。

**给我们的建议**

| 档 | 用途 | 建议值（**估计值**，按 Linear/Geist 推） |
|---|---|---|
| 0 · 无 | 页面、内嵌区 | 无阴影，靠面色差 |
| 1 · base | 卡片 | `0 1px 2px rgba(0,0,0,.04)`（保持） |
| 2 · raised | 下拉、悬浮条 | `0 4px 8px rgba(0,0,0,.06)` |
| 3 · overlay | 弹窗、抽屉 | `0 8px 24px rgba(0,0,0,.12)`（保持） |
| 4 · ring | 需要"描边感"的容器 | `0 0 0 1px rgba(0,0,0,.06)` **替代 border** |

> 关键：**一个元素只能有一档**。现在卡片同时有 border + shadow，属于"画两次"。

### 2.6 动效与反馈

**我们现在的实际值**（全文件扫描）：

| 项 | 数量 |
|---|---|
| `transition` | **4 处**（其中 2 处是 `none`，2 处是进度条宽度动画） |
| `@keyframes` | 1 个 |
| `animation:` | 4 处 |
| `prefers-reduced-motion` 保护 | **有** ✅（2 处） |

**结论：动效几乎为零。** 按钮 hover、卡片出现、页面切换、弹窗打开**全部是瞬移**。

> 说明：**没有视频材料**（我们只有静态截图），所以本节是**建议值**，不是从现有动效反推的。

**标杆怎么做的**

- **Material 3 在 2025-05 换掉了 easing+duration 体系，改用"弹簧物理"（motion physics）**：
  - 两套预设：**expressive**（有回弹，用于"高光时刻"）/ **standard**（最小回弹，**用于工具型产品**）。
  - 弹簧三参数：**stiffness**（硬度，越高越快）、**damping**（阻尼，越高越快停；=1 时完全无回弹）、**initial velocity**（初速度）。
- **Linear 的动效哲学**（从其克制风格推，**估计**）：短、快、无回弹。

**通俗解释**：
> 我们做的是**工具**不是玩具，所以用 M3 的 **standard**（几乎不回弹）而不是 expressive。
> 好的工具动效有个朴素标准：**用户不该"注意到"动画**，只该觉得"顺手"。所以时长要短（100–200ms），一旦超过 300ms 就会觉得卡。

**给我们的建议（全部为估计值）**

| 场景 | 建议 | 说明 |
|---|---|---|
| 颜色/背景变化（hover） | `transition: 120ms ease-out` | 最基础的一档，全站默认 |
| 按钮按下 | `transform: scale(0.98)` + `60ms` | 给"按到了"的触觉暗示 |
| 列表行 hover | `80ms` | 比按钮更快，因为鼠标扫过频率高 |
| 弹窗出现 | fade + `scale(0.98→1)`，`180ms` `ease-out` | M3 standard 的近似 |
| 弹窗关闭 | `100ms` `ease-in` | 关闭永远比打开快 |
| 页面切换 | **不做**（或 ≤100ms 淡入） | 工具产品里页面切换动画会拖慢操作 |
| 骨架/加载 | 静态占位，不闪烁 | 闪烁比静止更烦 |
| 进度条 | 已有 400/500ms ✅ 保持 | |
| reduced-motion | 已有 ✅，**新加的必须一并覆盖** | |

## 3 关键风格元素提炼（如果要一句话说清该往哪走）

1. **压缩的亮度层级**：层与层之间只差几个 RGB 值，靠"面色"分组而不是靠线框（Linear）。
2. **极窄的圆角上限**：最大 8px，不上 12/16；胶囊只给 tag/badge（Linear）。
3. **克制的字重**：400 / **510** / **590**，不用 600/700（Linear）。
4. **纯黑透明阴影 + 单一 elevation 档**：不含彩色，一个元素只一档（Linear + Geist）。
5. **ghost 按钮为默认**：只有主 CTA 有底色（Linear）。
6. **动效快而短**：100–200ms，standard 而非 expressive（M3）。

## 4 重构建议（按"性价比"排序）

### P0 —— 观感收益最大、改动最小（估计 0.5 天）

| # | 动作 | 为什么先做 |
|:--:|---|---|
| 1 | **加动效基座**：全局 `transition: 120ms ease-out`（颜色/背景），按钮按下 `scale(0.98)` | 现在"瞬移感"是最明显的廉价感来源；改动只是一个 CSS 变量 + 几条规则 |
| 2 | **弱化边框**：`gray-6` → `gray-4`，或卡片改 ring shadow | 直接把"表格感"降下来 |
| 3 | **指标卡不再整块染色**：语义色只染数字/图标 | 现在三张黄/绿卡会压过真正的内容 |

### P1 —— 结构性改动（估计 1 天）

| # | 动作 |
|:--:|---|
| 4 | 字号 7 档收敛到 6 档，`--fs-sm`/`--fs-md` 合并；字重换 510/590 |
| 5 | elevation 定 4 档（base/raised/overlay/ring），并把"卡片 border+shadow 双层"改成单一档 |
| 6 | 徽章改 pill；图标统一 16/20 两档；按钮 padding 回到 4 网格 |

### P2 —— 需要单独评估（各 0.5–1 天）

| # | 动作 | 风险 |
|:--:|---|---|
| 7 | 侧栏可收起（220 → 56） | 要改布局与图标态，动到多个页面 |
| 8 | 内容最大宽 1160 → 1320/1440 | 会改变所有页面的换行与栅格，要逐页看 |
| 9 | **清理 CSS 重复定义**（技术债） | 现在 `.side` 定义 **3 次**、`.content`/`.card`/`.stats`/`.two-col`/`.btn` 各 **2 次**；改哪个生效全靠"谁在后面" |

> 第 9 条是**必须先做的前置**：现在改样式时，很可能改了"前面那条"而实际生效的是"后面那条"。
> 这不是审美问题，是**会让后续所有调整都不可预测**的问题。
