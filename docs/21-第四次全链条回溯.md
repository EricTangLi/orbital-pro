## 5 开发计划检查（本次发现的问题）

### 5.1 `PLAN.md` 与事实不符

| 字段 | 修复前 | 事实 | 修复后 |
|---|---|---|---|
| 当前任务 | `T-M1-06` 三进程启动器 | 早已 done | M1 收尾（T-M1-12 partial） |
| 上一任务 | `T-M1-05` | 落后 6 个任务 | `T-M1-11`（已完成） |
| 测试数 | 43 | **46** | 46 |

**这会直接误导下一个人**：让他从已完成的三进程启动器开始。

### 5.2 门禁的两个漏洞（已修 + 有红绿证据）

**漏洞 1：解析抓错**
```powershell
# 修复前
$m = [regex]::Match($plan, 'T-M\d+-\d{2}')   # 抓全文第一个！
```
而 `PLAN.md` 的"命令速查"里有 `check-plan.ps1 -TaskId T-M1-00` →
**永远解析成 T-M1-00**，门禁一直在校验**错误的任务**。

**漏洞 2：不校验任务状态**
只检查"任务卡存在"，不检查 `status`。
⇒ 把"当前任务"设成一个 done 的任务，门禁照样 PASS。

**修复后的红绿对照**（本轮实跑）：
```
红（当前任务 = T-M1-06，done）：
  当前任务 = T-M1-06
  FAIL 当前任务 T-M1-06 的状态是 done —— 已完成的任务不应作为「当前任务」
  CHECK-PLAN: FAIL (1 项) —— 不许开工      exit=1

绿（当前任务 = T-M1-12，partial）：
  当前任务 = T-M1-12
  ok   当前任务 T-M1-12 状态=partial
  CHECK-PLAN: PASS —— 可以开工             exit=0
```

**这是本项目第一次给"计划门禁"本身做红绿对照**——之前只给业务代码做。
